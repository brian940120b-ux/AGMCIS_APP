## 1. 為什麼 Phase 7 不夠

Phase 7 的回測引擎只回答「這組參數在這段歷史上表現如何」。
那個問題本身沒有用 —— **任何策略只要參數夠多,都能在一段固定歷史上
做出漂亮的曲線。**

Phase 8 回答的是另一個問題:**這個表現是真的優勢,還是過擬合?**

## 2. 四種檢驗

```
agmcis/lab/
  splits.py       時間序列切分(IS/OOS、Walk Forward)
  runner.py       在切好的資料上跑引擎,保證參數只用訓練段挑
  montecarlo.py   交易序列重抽樣、破產機率
  scoring.py      最佳化目標 + Strategy Health Score + 過擬合偵測
  evaluate.py     完整流程的單一入口
  ensemble.py     通過驗證的策略組成投資組合
```

### 2.1 切分一律是時間序列切分

金融資料隨機打散再切 train/test 是典型的資料洩漏:測試集裡會出現訓練集
後面的 K 棒,而相鄰 K 棒高度相關,等於間接看過答案。
`splits.py` 只提供時間序列切分,而且每一段測試資料都**緊接在自己的訓練資料
之後、從不重複使用**。

資料不夠切時**拋例外**,不是回傳空 list —— 靜默的空結果會被讀成
「驗證過了,只是沒有視窗」。

### 2.2 Walk Forward

每一段都重新用自己的訓練視窗挑參數,再在緊接著的測試視窗驗證。
這模擬的是真實使用方式:你只會用過去的資料調參。

看的是**一致性**,不是最好的那一段。只有一個視窗特別好、其他都不行,
那是運氣。一致性低於 50% 會直接變成 blocker。

另外會警告一種很好認的過擬合:**每個視窗挑出來的最佳參數都不一樣**,
代表參數在跟雜訊對齊。

### 2.3 Monte Carlo

用 **R 倍數**(單筆損益 ÷ 單筆風險)重抽樣,因為 R 與部位大小無關。
輸出報酬分佈、回撤分佈、獲利機率、**破產機率**。

兩個前提寫在模組說明裡,因為不寫會被過度解讀:

- 假設每筆交易彼此獨立。實際上連虧常常成群出現,所以真實回撤通常**更糟**。
- 只能重抽已經發生過的交易。歷史上沒出現過的極端行情不會憑空生出來。

### 2.4 最佳化目標不是報酬率

Master Prompt 第二節寫得很清楚:目標是
Risk Adjusted Return + Positive Expectancy + Robustness + Low Drawdown + Consistency。

```
score = expectancy_r × 樣本數信心 ÷ (1 + 最大回撤比例)
```

期望值 <= 0 直接回負分,不管報酬率多好看。
`scoring.objective()` 存在的理由,就是讓「用總報酬率挑參數」變得不方便。

## 3. Strategy Health Score

0-100,但**分數高不等於可以上線**。這是一組「能不能拒絕」的判準。

任一 blocker 成立 → REJECT,而且**分數直接歸零**。
留著「REJECT 但 85 分」這種組合,看報告的人遲早會去凹那個 85。
分項合計留在 `raw_score` 供診斷。

Blocker:

| 條件 | 理由 |
|---|---|
| OOS 交易 < 30 筆 | 樣本太小,數字再好看也不足以下結論 |
| OOS 期望值 <= 0 | 長期必定虧損 |
| OOS Profit Factor < 1 | 同上 |
| OOS 最大回撤 > 40% | 實際上撐不過去 |
| IS → OOS 期望值退化 >= 80% | 典型的過擬合 |
| OOS 出現強制平倉 | 槓桿或停損設定有問題 |
| Monte Carlo 破產機率 > 5% | 這個風險比例下不能跑 |
| Walk Forward 一致性 < 50% | 不穩定 |

評分**以 OOS 為主體**。IS 的表現只用來偵測退化,不加分 ——
在調參用過的資料上表現好本來就是應該的,那不是證據。

實測一例(合成資料):某策略 OOS 期望值 2.60 R、Walk Forward 一致性 100%、
分項合計 85.9 分,但只有 6 筆交易 → **REJECT**。這正是要的行為。

## 5. 一條直通實單的污染路徑

`generate_optimizer_bonus.py` 的輸出會被 `smart_ranking.py` **直接加進
最終評分**,也就是直接影響實際下單。

它原本的加權來自**回測總報酬率** —— 那條路徑等於
「在一段歷史上擬合得越好的標的,live 分數加越多」,把過擬合原封不動送進實單。
而且驗證失敗的標的會拿到 **-10**,等於因為「我們沒能驗證它」而懲罰它。

現在加權只由驗證判定與 OOS 期望值決定:

```
PASS      -> 依 OOS 期望值分級,0.30 R 以上給滿分 10
MARGINAL  -> 固定 +2
REJECT    -> 0(中性,不是負的)
ERROR     -> 0(中性)
```

## 6. Ensemble

- **REJECT 的策略權重是 0**,不是「權重小一點」。
- 權重來自 **OOS 期望值 × Walk Forward 一致性**,不是 IS。
- 單一策略權重上限 50%,避免組合退化成單押。
  成員太少時上限會把權重壓成完全平均、抹掉差異,所以上限只在
  真的能限制集中度時才套用。
- 被拒絕的策略**留在報告裡並附理由** —— 只列入選者,
  看報告的人不會知道有多少東西被試過又丟掉。
- 全部沒通過時組合是空的,並明說「這是正確的結果,不是錯誤」。

## 7. 測試

```

  tests/test_strategy_optimizer.py  18
```

測試的重點不是「好策略會通過」,而是**驗證層會不會拒絕**:

- 6 筆交易的 2.6 R 期望值 → REJECT
- IS 0.50 R、OOS 0.02 R → REJECT,理由標示為過擬合
- 沒有虧損單 → Profit Factor 不計為無限大
- 崩潰的策略 → 記成 error,不是 0 分
- `optimise()` 回傳**每一組**參數的結果,不是只回最好的那組

兩個特別針對「安靜地算錯」的測試:

- `test_a_slice_maps_back_to_the_same_rows_as_the_full_frame` ——
  Lab 傳子區間給策略,但舊策略模組的指標掛在整個 DataFrame 上。
  對位錯了不會拋例外,只會安靜地用錯的 K 棒算訊號。
- `test_indicator_values_do_not_change_when_future_candles_are_added` ——
  指標是在整段(含 OOS)資料上算的。只要每一列只依賴自己以前的價格
  就不構成洩漏,這個測試把那件事釘住。

另外驗證層本身也要能說 YES:`test_a_genuinely_solid_result_can_pass`。
一個永遠說 NO 的驗證層跟永遠說 YES 的一樣沒有資訊。
