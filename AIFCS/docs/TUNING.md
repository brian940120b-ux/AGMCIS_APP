## 四、規則明文允許我們改的 ← **這裡就是可以贏的地方**

### 4.1 演算法：幾乎不限

> 可以使用 Rule-Base、行為樹、決策樹、貝葉斯、AI、機器學習、深度學習、
> 強化學習、LLM、等**非人工干預**之控制技術

**混合式是合法的。** 純 RL 不是規定。例如「RL 主控 + 規則式防墜底線」完全可行 ——
以我們目前的墜毀率來看，這可能比再多練幾百萬步有用。

### 4.2 整個連線程式：可以重寫

> 參賽方可根據本程式進行修改、或是**重新以其他程式語言撰寫**，
> 並無強制限制需要按照本範例進行開發

**所以下面每一個數字都是我們的**，不是 HOST 的：

| 參數 | 範例程式的值 | 規則上限 | 備註 |
|---|---|---|---|
| 死區 | `[0.01, 0.03, 0.06]` | 無 | 小輸入被吃掉 |
| 指數曲線 | `[1.0, 3.0, 3.0]` | 無 | 升降舵/方向舵被三次方大幅衰減 |
| 每幀變化上限 | `[0.050, 0.026, 0.013]` | 無 | **升降舵滿舵要 0.64 秒** |
| 油門變化率 | `0.004` / 幀 | 無 | 0→1 要 4.2 秒 |
| **方向舵上限** | **0.2** | **±1** | 差 5 倍 |
| 高速升降舵限制 | Mach 0.8 以上 0.4 | 無 | 自己加的 G 限制器 |

**最值得注意的是方向舵。** 三個數字在打架：

- **規則（表 2）：±1**
- 範例連線程式：clip 到 ±0.2
- 範例**訓練**環境的動作空間：釘死在 `[0, 1e-17]`

第三個代表**主辦方那顆 3.14 億步的模型從來沒動過方向舵**。用其他隊多半也是照抄
那個動作空間。**方向舵是規則允許、而對手很可能不會用的操作面。**

⚠️ 但每幀變化上限拿掉要小心：拉太猛會超過 9G，**每秒扣 1000 分**，而追蹤一秒
才賺 2000。整形不全是累贅，它也是個 G 限制器。**要 A/B，不要憑感覺改。**

### 4.3 訓練環境：完全是我們的

> A. 訓練階段軟體訓練程式：本程式為供參賽者快速上手之範例…**後續需要各參賽者
> 自行修改**

獎勵函數、對手、初始條件分布、課程學習、self-play —— 全部隨我們。

### 4.4 回合之間可以換模型

> 注意事項 3：參賽者可於單回合結束時且於新一回合開始前**切換模型或切換演算法**
> （回合切換 3 分鐘）

**這是一個戰術層面的機會。** 5 戰 3 勝的話，第一回合打完就知道對手的風格，
第二回合可以換一個針對性的模型。前提是我們手上要有**不只一個**訓練好的模型。

## 六、怎麼比較

```python
from competition.evaluate import evaluate, load_policy, compare
from competition.environment import EnvConfig

a = evaluate(load_policy("models/competition/run1"), EnvConfig(),
             rounds=20, seed=1000, label="reference reward")
b = evaluate(load_policy("models/competition/score1"), EnvConfig(),
             rounds=20, seed=1000, label="score reward")    # 同一批種子
print(compare([a, b]))
```

`seed` 必須相同,不然比的是兩批骰子,不是兩個策略。

## 七、超參數（2026-09-26 新增）

`TUNING.md` 前面幾節講的是「規則准不准」。這一節講**設定對不對** —— 查下去才發現
前三名的問題都在這裡，而且主辦方的範例也有。詳見 `STRATEGY.md`。

```bash
# 建議的新 session（run1 當對照組，不要覆蓋它）
train.bat --name g999 --reward score --gamma 0.999 --gradient-steps -1 --timesteps 5000000
```

| 旗標 | 預設 | 建議 | 為什麼 |
|---|---|---|---|
| `--gamma` | 0.99 | **0.999** | 0.99 的視野只有 **1.7 秒**，擊殺要 **3 秒** |
| `--gradient-steps` | 1 | **-1** | 8 workers 下每 8 筆資料只更新 1 次 |
| `--learning-rate` | 3e-4 | 2e-4 | 主辦方用的值 |
| `--sde` | 關 | 可試 | 主辦方開著 |

啟動時會印出視野，不用自己算：

```
horizon:  gamma 0.999 — 16.7 s of future at 60 Hz
```

**這些現在會記進 session。** 換了其中任何一個，續練會被擋下來並說明差在哪 ——
和換 reward、換環境一樣，因為那確實是不同的實驗。

已經在跑的 session（例如 run1）**不受影響**：它們沒記錄過這些設定，所以不會
被判定為不一致。

## 八、2026-09-26 全部做完的東西

### ⚠️ 先更正一個建議

我前面建議 `--reward score`。**實測之後那是錯的。**

搖桿置中必定墜毀的整回合,四種獎勵的總分:

| 模式 | 總獎勵 | |
|---|---|---|
| `reference` | −10,477 | |
| **`score`** | **+174.6** | ← **墜毀卻拿正分** |
| `margin` | −29.9 | ✅ |
| `shaped` | −71.9 | ✅ |

位置優勢分永遠 ≥ 0,而墜毀只扣一次 −10。2,928 幀的正分把它淹掉了。
**`score` 會教策略「撞地沒關係」。**

### 新的獎勵模式

| 模式 | 是什麼 | 用途 |
|---|---|---|
| `reference` | 主辦方的 | 對照組 |
| `score` | 競賽計分,單邊 | **量測用,不要拿來訓練** |
| **`margin`** | 我方減對方 | 規則比的就是這個差 |
| **`shaped`** | margin + 論文缺的項 | 攻擊錐太窄,需要坡度 |

`shaped` 補的是:朝機首方向的**軟坡度**(1° 硬指標在策略沒進去過之前梯度是零)、
`Γ_B(d)` 距離窗、衝過頭懲罰、接地懲罰。

### 防墜底線 —— 效果最大的一項

```bash
train.bat --ground-avoidance
```

規則明文允許(公告說明 一.1.(2) 把 Rule-Base 和強化學習並列)。

**實測,搖桿置中的策略對上參考對手:**

| | 墜毀率 | 勝率 | 分差 |
|---|---|---|---|
| 無地板 | **100%** | 0% | −19 |
| **有地板** | **0%** | **67%** | **+32** |

每一回合都撐滿五分鐘。**這是一個什麼都不做的策略。**

> 第一版我把升降舵正負號搞反了,結果它**更早**撞地(2766 對 2928 幀)。
> 實測 +0.5 升降舵三秒內把俯仰角帶到 −14.7°,**正號是機首向下**。
> 已修,而且有三個測試會抓這個錯。

### Action repeat

```bash
train.bat --action-repeat 6      # 10 Hz,PHANG-MAN 高階策略的頻率
```

⚠️ **`--timesteps` 現在數的是決策,不是幀。** repeat 6 的話,500 萬「步」= 3000 萬幀。
啟動時會印出來:

```
decisions: every 6 frames (10 Hz) — 3,000 per round, and --timesteps counts these, not frames
horizon:  gamma 0.995 — 20.0 s of future
```

⚠️ 比賽端**同步改了**,而且有對等測試。訓練和當天必須一致,否則策略會遇到它沒練過的飛機。

### 其餘新旗標

| 旗標 | 預設 | 說明 |
|---|---|---|
| `--rudder-limit` | 0.2 | 規則表 2 允許 ±1 |
| `--hidden` | 256 256 | PHANG-MAN 用單層 12288 |
| `--relu` | 關 | PHANG-MAN 用 ReLU |
| `--gamma` | 0.99 | 會依 action repeat 正確換算視野 |
| `--gradient-steps` | 1 | `-1` 才是每筆資料一次更新 |

### 建議的第一個新 session

```bash
train.bat --name v2 --reward margin --ground-avoidance --action-repeat 6 \
          --gamma 0.995 --gradient-steps -1 --timesteps 2000000
```

`--gamma 0.995` 配 repeat 6 是 **20 秒**視野。
`--timesteps 2000000` 個決策 = 1200 萬幀,大約等於 run1 的 6 倍飛行量。

**run1 不要動,它是對照組。** 跑完用 `evaluate.py` 相同 seed 配對比較。
