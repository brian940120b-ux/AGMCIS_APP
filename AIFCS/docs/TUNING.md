# 參數優化 — 可以動什麼，怎麼動

**前提：沒有量尺就沒有優化。** 到今天為止我們沒有一個「用主辦方的判定規則去量模型」
的工具，所以每一個調參決定都只是猜。`backend/competition/evaluate.py` 補上了這個洞：
固定種子跑完整回合，用 `decide_round`（主辦方的判定表）算勝負，兩個模型跑**同一批**
對戰再比較。

---

## 動不了的（HOST 說了算）

| | |
|---|---|
| 封包格式、60 Hz、握手 | 主辦方的介面 |
| 計分公式、距離係數、攻擊包絡 | 主辦方的裁判 |
| 回合 300 秒 | 主辦方的規則 |
| 搖桿整形（死區、指數、變化率上限） | **HOST 端執行**，我們送什麼它都這樣處理 |
| 當天的對手 | 別隊 |

我們唯一能送出去的是四個數字：副翼、升降舵、方向舵、油門。**其他都是 HOST 的。**

---

## 能動的，按預期效益排序

### 1. 獎勵函數：`reference` → `score`　【建議改，理由最強】

實測兩把尺（機首正對、位於對方正後方、距離不變）：

| 距離 | reference 每幀 | competition 每秒 |
|---|---|---|
| 200 m | 2.00 | 3,440 |
| 400 m | 2.00 | 3,440 |
| 800 m | 2.00 | 3,200 |
| 1500 m | 2.00 | 600 |
| 3000 m | 2.00 | 120 |
| 6000 m | **2.00** | **120** |

**參考獎勵對距離完全平坦。** 200 公尺和 6 公里給一樣的分。但競賽計分在 6 公里
只剩 3.5%。

一個把參考獎勵最大化的策略，可以在**兩英里外**把鼻子對準敵機、拿滿獎勵、
**然後在比賽拿幾乎零分**。

```bash
train.bat --name score1 --reward score
```

⚠️ 換 reward 會讓現有 session 拒絕續練（這是對的 —— 兩種條件混在一起的模型卡
只能對其中一個誠實）。**要開新的 `--name`，不要覆蓋 run1。**

### 2. 甜蜜點：152–500 m　【已隱含在 `score` 裡】

兩條規則的交集，算出來的，不是猜的：

| 距離 | 距離係數 | 在攻擊包絡內? |
|---|---|---|
| < 150 m | 0.1 | ❌ 太近 |
| 150–152.4 m | **1.2** | ❌ 太近（差 2.4 m） |
| **152.4–500 m** | **1.2** | ✅ | ← **這裡** |
| 500–914 m | 1.0 | ✅ |
| 914–1500 m | 1.0 | ❌ 太遠 |
| > 3000 m | 0.1 | ❌ |

**152.4–500 公尺（500–1640 呎）同時吃到最高距離係數和擊墜機會。**
`ScoreReward` 用的就是主辦方的 `position_advantage`，所以這個偏好自然存在，
不用另外加項。

（那 2.4 公尺的縫隙是規則自己造成的：距離係數用公尺，攻擊包絡用呎。）

### 3. 方向舵解鎖　【值得做 A/B】

主辦方的動作空間把方向舵釘在 `[0, 1e-17]`，**參考策略從來沒用過它**。但搖桿整形
是照 ±0.2 寫的 —— **HOST 會處理我們送出去的 yaw**。

所以這是一個**合法而且對手做不到**的操作面。代價是動作空間變大，學得慢一點。

```bash
train.bat --name rudder1 --reward score --rudder
```

### 4. 速度：已經領先了　【確認過，不用動】

主辦方參考環境把速度設在高度**之前**，導致校正空速在海平面解算，結果**慢 106 節**。
他們那個 3.14 億步的模型是在 **Mach 0.47** 練出來的。

實測真實 HOST：**Mach 0.673**。

我們的預設是對的順序。**不要**加 `--reference-speed-order`。這是一個已經到手的優勢。

### 5. 生存優先　【先觀察，不急著改】

搖桿置中 49 秒撞地（見 `CONFORMANCE.md`）。策略要先學會活著。

如果長時間訓練後墜毀率還是很高，可以考慮縮短初期回合長度做課程學習 —— 但那是
**環境變更**，會讓 session 不能續練，而且是架構層級的改動。**先看數據再決定。**

### 6. 訓練初始條件　【開新 session 時再考慮】

我們訓練用規格的 3000/6000/9000 三個離散距離。真實比賽如果也是這三個就最好；
如果是連續隨機（像測試 HOST 那樣），只練三個點可能過擬合。

`--reference-setup` 可以改成 0–12,000 ft 連續。**這也是環境變更。**

## 怎麼比較兩個模型

```python
from competition.evaluate import evaluate, load_policy, compare
from competition.environment import EnvConfig

a = evaluate(load_policy("models/competition/run1"), EnvConfig(),
             rounds=20, seed=1000, label="reference reward")
b = evaluate(load_policy("models/competition/score1"), EnvConfig(),
             rounds=20, seed=1000, label="score reward")   # 同一批種子
print(compare([a, b]))
```

```
                          won   killed    died  crashed      margin  152-500m
reference reward         25%      17%      0%      58%      -1,204       3.1
score reward             55%      42%      0%      25%      +8,910      41.7
```

**`seed` 必須相同** —— 不然比的是兩批不同的骰子，不是兩個策略。

### 每個欄位是什麼

| 欄位 | 意思 |
|---|---|
| `won` | 依 `decide_round`（主辦方判定表）的勝率 |
| `killed` | 累積 3 秒追蹤達成率 |
| `died` | 被對方達成 |
| `crashed` | 撞地率 —— **早期訓練這個最該看** |
| `margin` | 我方 `S_advantage` 減對方，平均。當天的決勝分 |
| `152-500m` | 每回合待在甜蜜點的秒數 |

---

## 優先順序

1. **先讓 run1 跑完** —— 它是對照組，沒有對照組就沒有比較
2. 跑完後 `evaluate` run1，拿到基準線
3. 開 `--reward score` 的新 session，練到同樣步數，配對比較
4. 贏的那個再開 `--rudder` 分支比一次
5. **配平那件事要靠 HOST 驗證**（見 `CONFORMANCE.md`），那是目前最大的未知數
