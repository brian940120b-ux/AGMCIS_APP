## D：規格有歧義，我做了選擇

### 1. 攻擊錐半角 1°（全角 2°）

圖上的箭頭橫跨整個錐，而參考環境是拿**它自己的追蹤角**（依定義就是半角）去和
1.0 比。所以半角 1°。

**如果我讀錯了**，真正的錐比較寬鬆，用比較嚴的標準練出來的策略照樣能得分；
反過來錯才會讓我們把沒打到的算成打到。**這個方向的錯是安全的。**

### 2. `ΣP_t` 每幀累加，不是每秒

`W_pos = 10` 在 60 Hz 下，一個位置完美的秒值 1,440 分，對上追蹤一秒的 2,000 分，
這是個平衡。若每秒取樣一次就只有 24 分 —— 一個值 24 分的項不會配一個權重、
一張表和一張圖。

### 3. `T_G` 是超過 9G 的秒數

取自 OBS 封包裡的駕駛員 Z 軸過載。

### 4. 方向舵：整形寫 ±0.2，動作空間卻鎖死

主辦方的動作空間把方向舵釘在 `[0, 1e-17]`，**所以參考策略從來沒用過方向舵**；
但同一套搖桿整形是照 ±0.2 寫的。**整形才是誠實的那個** —— 它描述 HOST 會怎麼
處理我們送出去的 yaw 值。見下面的優化建議。

## E：沒驗證過（風險）

### ⚠️ 最高風險：回合開始時飛機有沒有配平

我們（照抄參考套件）**沒有呼叫配平**。IC 只設 `theta=0, phi=0` 就跑。

實測我們的環境，搖桿置中、油門保持 0.8：

```
 t=5s   14,367 ft  pitch  -7.6°  388 KCAS
 t=20s  10,662 ft  pitch -20.0°  554 KCAS
 t=49s     164 ft  pitch -16.1°  694 KCAS   → 墜毀
```

**搖桿置中 49 秒撞地。** 每個策略都得先學會「拉桿活下來」，才輪到學打仗 ——
這極可能就是我們 122,880 步的模型 0/6 全部墜毀的原因。

**這和參考套件一致，但和真實 HOST 一致嗎?不知道。** 如果 HOST 會配平而我們不會，
我們就是在訓練一架不存在的飛機。

**怎麼驗證（需要 HOST）：** 用探針送**純中立指令**（搖桿置中、油門 0.8），看 HOST
那架飛機是保持高度還是像我們一樣低頭。保持 → HOST 有配平，我們要補。
